# Evaluation protocol

## Contract v2 (current)

Module: `backend/app/quality` (`CONTRACT_VERSION = 2.0.0`). Every rendered variant receives a
`QualityReport` with per-check status (`pass | fail | needs_review | not_checked`), severity
(`critical | major | minor`) and a derived verdict:

- `accepted` — every implemented check passed;
- `needs_review` — a check needs a human, a minor check failed, or a critical check did not run;
- `failed` — a critical or major check failed.

Checks: `export_dimensions`, `design_understood` (flat image not decomposed), `required_element_present`
(headline/CTA/logo present in source must stay placed), `inside_canvas`, `text_overlap`,
`min_text_size` (measured vs estimated), `element_visible` (expected pixels vs composite; detects
occlusion and clipping), `text_legible` (tesseract OCR vs native string; OCR disagreement with
visible pixels is `needs_review`, never a silent pass).

Config, thresholds, environment (Python/Pillow/NumPy/OCR version) and generation context are
recorded inside every report. Legacy layout-metadata metrics remain available as `legacy_v1`
for historical comparison and must not be used for claims.

## Corpus

Current: 12 synthetic cases × 3 sizes (1200×628, 1080×1080, 1080×1920) generated by
`backend/tools/generate_bench_fixtures.py --cases 12 --seed 42` (scenarios: hero+headline+CTA+logo,
long text, large logo + long CTA, busy background, off-centre hero). Since contract v2 the
fixtures ship a clean `background.png` so foreground elements are not baked into the background.

Real corpus (≈30 masters, ≥5 brands, licensed): `BLOCKED_EXTERNAL`. Holdout split: to be frozen
when real designs arrive; synthetic cases are engineering fixtures, not customer validation.

## Commands

```bash
python backend/tools/generate_bench_fixtures.py --cases 12 --seed 42
python backend/tools/run_layout_bench.py --mode both  --seed 42   # baseline + phase21
python backend/tools/run_layout_bench.py --mode phase3 --seed 42  # phase3, production n_candidates
```

Outputs (not committed): `<outdir>/report.md`, `<outdir>/summary.json` (`run_config` + per-run
records with verdict, issues, legacy_v1, elapsed_s, config flags).

## Results (2026-09-09, seed 42, 12 cases × 3 sizes, contract v2)

| Mode | Accepted | Needs review | Failed | Legacy v1 "pass" |
|---|---:|---:|---:|---:|
| baseline (template, raster text) | 5/36 | 19 | 12 | 0/36 |
| phase21 (adaptive, raster text) | 0/36 | 14 | 22 | 20/36 |
| phase3 (procedural redesign, n=8) | 0/36 | 6 | 30 | 20/36 |
| design (native text, verify + bounded repair) | 32/36 | 4 | 0 | 13/36 |

Design-mode reviews: 4 busy/noise-background runs with low OCR agreement on CTA/sub text.
Environment: Python 3.11.15, Pillow 10.4.0, NumPy 1.26.4, tesseract 5.3.4, 4 CPUs.
Machine-readable: `summary.json` of each run (not committed; regenerate with the commands above).

Historical claim "31/36 (86.1%) Phase 3 pass" (`BENCH_DELTA_PHASE3_QUALITY.md`) came from the
legacy evaluator and included the preserved false positive; it is not comparable.

## Metrics still to instrument

Critical content-error rate and missed-error rate vs human labels; first-pass human acceptance;
operator time; edit operations to approval; latency distribution and failure rate; cost per
approved variant; generalization to held-out sizes/campaigns/brands; fidelity after
save/reopen/export round trips.
